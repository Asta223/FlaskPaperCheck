## BugFix：VS Code Flask 扩展启动连 MySQL 报 500

用户用 VS Code Flask 扩展启动（`python -m flask run`），POST /auth/login 报 500：`Can't connect to MySQL server on 'localhost'`。

**根因**：用户在终端 set 的 `DB_ENGINE=sqlite` 不被 VS Code 扩展进程继承；项目 `.env.example` 声称自动读取 .env，但 `config.py` 无加载逻辑且未装 python-dotenv，配置永远走默认 MySQL。

**修复（commit f3b36be）**：config.py 顶部加纯标准库 `_load_dotenv()`（零新增依赖，env 变量优先于 .env），创建本地 `.env`（DB_ENGINE=sqlite，已 gitignore 不入库），更新 .env.example/README；另加"无任何 DB_* 配置且无 .env 时回退 sqlite"逻辑（原为默认 MySQL）。

**QA 独立回归（ROUTE: NONE）**：零环境变量下 create_app 自动读 .env → sqlite URI + SECRET_KEY 正确；登录链路（302→200→带 CSRF POST→302→登录后 200）无 500；env > .env 优先级成立；生产 MySQL 场景（DATABASE_URL / DB_ENGINE=mysql / 任意 DB_* 分项）不受损；212 pytest + 39 冒烟全绿；改动仅 config.py/.env.example/README，app/ 与测试零改动。

**结论**：VS Code 方式启动无需再手动设置环境变量即可连 SQLite。非阻断建议：零配置回退 sqlite 时可加警告日志防止生产静默降级。

## BugFix：侧边栏分组点击仍无反应（用户第 3 次反馈）
- **真正根因（代码层）**：`base.html` 原生 JS 点击处理里状态判断写反——`var nowCollapsed = !panel.classList.contains('show')`，展开时算出 `false`，`applyState(false)` 又把它设回展开；收起时算出 `true`，再 `applyState(true)` 保持收起。结果点击永远不改变状态，与浏览器、CDN、localStorage 均无关。
- 修复：改为 `var shouldCollapse = panel.classList.contains('show')`（当前展开→收起，当前收起→展开），保存的 localStorage 值也同步为实际状态。
- **第二次根因（环境层）**：运行中的 Flask 进程（PID 10452/31140）仍是从旧目录 `E:\flaskProject\FlaskPaperCheck` 启动的，修改当前目录模板后服务端 `curl` 仍返回旧 JS（已用 grep 验证）。Stop-Process 清理后从 `E:\个人项目\FlaskPaperCheck` 用 venv Python 重启 `flask run --host 127.0.0.1 --port 5000`，重新登录抓页面确认返回新逻辑。
- 验证：Node 模拟点击逻辑展开→收起→展开正确；服务端 HTML 含 `shouldCollapse` 新代码；当前服务 `.env` 仍指向 MySQL `FactoryManagementSystem`。
