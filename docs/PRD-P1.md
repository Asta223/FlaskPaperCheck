## 3. 逐条需求规格

> 优先级列均为 P1，括号内为表 2 的建议实现顺序。验收标准均可测（Given/When/Then 或清单）。

### P1-01 请假申请与部门主管审批流（顺序 4）

**用户故事**
- 作为普通员工，我想在线提交请假申请（类型/起止时间/事由），以便免去纸质单据并留存凭证。
- 作为部门主管，我想审批本部门员工的请假（批准/驳回并记录意见），以便控制部门出勤。

**验收标准**
- Given 员工登录，When 提交一条合法请假（类型、起止时间有效，跨度>0），Then 生成 `pending` 申请，申请人/所属部门自动带入，可在"我的请假"查看。
- Given 结束时间早于开始时间或跨度为 0，When 提交，Then 拒绝并给出字段级错误提示。
- Given 部门主管登录，When 打开"待我审批"，Then 仅见本部门（含子部门，见默认假设 A5）的 `pending` 申请；批准/驳回后状态更新，并记录审批人、审批时间、审批意见。
- Given 非审批人尝试对他人申请执行审批 POST，When 请求，Then 返回 403。
- Given 请假被批准，When 统计该时段出勤，Then 该时段标记为请假、不计缺卡、不判迟到早退（与 P1-02/P1-03 联动）。

**依赖与前置**：P1-04（部门范围过滤）；`LeaveRequest` 模型；权限点 `attendance.leave.apply` / `attendance.leave.approve`。

---

### P1-02 迟到/早退自动判定（顺序 3）

**用户故事**
- 作为部门主管，我想系统自动标记每日签到是否迟到、签退是否早退，以便客观掌握出勤。
- 作为普通员工，我想看到自己某天被标记迟到/早退及对应分钟数，以便核对。

**验收标准**
- Given 工作日签到时间晚于上班宽限阈值（默认 09:15，见默认假设 A2），When 签到，Then `AttendanceRecord.late_minutes > 0` 且状态含"迟到"。
- Given 签退时间早于下班宽限阈值（默认 17:45），When 签退，Then `early_leave_minutes > 0` 且状态含"早退"。
- Given 正常签到签退，When 查询记录，Then 状态为"正常"，两项分钟数为 0。
- Given 判定结果，When 查看个人记录与部门汇总，Then 迟到/早退状态与分钟数可见。
- 判定结果落库（非渲染时实时计算），阈值调整不影响已产生的历史判定；请假/缺卡日不判迟到早退。

**依赖与前置**：`AttendanceRecord` 增字段（迟到/早退分钟、状态）；阈值集中配置；P1-01（请假豁免）。

---

### P1-03 部门考勤汇总（顺序 5）

**用户故事**
- 作为部门主管，我想按月查看本部门员工的出勤/迟到/早退/请假/缺卡汇总，以便掌握部门出勤全貌。

**验收标准**
- Given 部门主管登录，When 打开"考勤→部门汇总"并选择月份，Then 表格列出本部门（含子部门）每位员工的：出勤天数、迟到次数、早退次数、请假天数、缺卡天数。
- Given 手工篡改请求参数试图查看非管辖部门，When 请求，Then 数据被数据权限收窄为本部门（不报错、不返回越权数据）。
- Given 点击某员工行，When 展开，Then 显示其当月每日明细（日期/签到/签退/状态）。
- 汇总结果可作为 P1-16 CSV 导出的数据源。

**依赖与前置**：P1-04、P1-02、P1-01；权限点 `attendance.summary.view`。

---

### P1-04 部门数据权限隔离（顺序 2）

**用户故事**
- 作为系统管理员，我想让部门主管只能看到本部门数据，以便防止跨部门数据泄露。
- 作为部门主管，我想只看本部门的人员/考勤/工单，以便聚焦职责范围。

**验收标准**
- Given 用户为部门主管（`leader` 角色且为某 `Department.leader_id`），When 访问 `hr/employees`，Then 仅返回本部门及子部门员工。
- When 访问考勤月度/汇总/请假审批，Then 数据范围同上。
- When 访问 `production/orders`，Then 仅返回归属部门（`related_department_id`，见默认假设 A5）或负责人属于本部门的工单。
- Given `superadmin` 角色，When 访问上述页面，Then 全量数据不受限。
- **边界**：数据权限只做"可见性收窄"，不提升功能权限——无 `attendance.view_all` 的主管仍不能查看全公司数据；实现集中在各蓝图 `base_query` 单一出口（架构已预留），不改多处路由。

**依赖与前置**：`WorkOrder.related_department_id`（新增）；`Department.leader_id`（P0 已有）；各蓝图 `base_query` 出口（P0 已有）。

### P1-05 工单领料关联（顺序 8）

**用户故事**
- 作为生产管理员，我想在工单详情发起领料（选物料/仓库/数量），以便生产用料与工单绑定、成本可追溯。
- 作为仓管员，我想在出库单上看到关联工单，以便核对用料去向。

**验收标准**
- Given 工单状态为 `pending` 或 `in_progress`，When 在详情页点击"领料"并提交（物料/仓库/数量），Then 生成出库单（`doc_type=out`、`related_order_id=本工单`）并扣减库存（复用 P0 库存事务与不足回滚）。
- Given 库存不足，When 提交，Then 拒绝、整体回滚、提示当前余量。
- 领料成功后，工单详情"物料领用"区显示领料记录（物料/数量/时间/经手人/单据号）。
- 每次领料自动写入工单操作日志（P1-06）与库存流水（P1-07）。
- Given 工单已 `completed`/`accepted`，When 领料，Then 禁止并提示。

**依赖与前置**：P1-07、P1-08、P1-15；权限点 `production.issue`。

---

### P1-06 工单操作日志（顺序 9）

**用户故事**
- 作为生产管理员/部门主管，我想查看某工单从创建到验收的全部操作记录（谁在何时做了什么），以便追溯进度与责任。

**验收标准**
- Given 打开工单详情，When 切换到"操作日志"页签，Then 按时间倒序展示：创建、工序状态流转、领料、工单状态变更等事件（操作人+时间+动作+摘要）。
- 工单/工序每次合法状态流转自动记一条日志；领料动作（P1-05）自动记一条日志。
- 日志只读，任何角色不得编辑或删除。
- 复用统一 `OperationLog`（P1-15），以 `target_type='work_order'`、`target_id=工单ID` 过滤展示（不另建工单专属日志表）。

**依赖与前置**：P1-15（统一日志基础设施）。

---

### P1-07 库存变动流水（顺序 6）

**用户故事**
- 作为仓管员，我想查看每个物料每次入库/出库的明细（含变动前后余额、时间、经手人、单据），以便对账和追溯。

**验收标准**
- Given 仓管员打开"仓库→库存流水"，When 按物料/仓库/日期/单据类型筛选，Then 列出：单据号、类型、物料、仓库、数量、变动前余额、变动后余额、经手人、时间、关联工单。
- 每条出入库单据（P0）及领料（P1-05）提交时同步生成一条不可变流水记录。
- 流水支持分页（`page/per_page=20`，沿用 P0 约定）与 CSV 导出（P1-16）。
- 期初/首次入库记为"入库"流水，变动前余额=0（默认假设 A4）；仅业务单据/领料产生流水，绕过单据直接改库不产生流水（一致性边界说明）。

**依赖与前置**：`StockLedger` 模型；权限点 `warehouse.ledger.view`。

---

### P1-08 出入库单据关联工单（顺序 7）

**用户故事**
- 作为仓管员，我想在录入出库单时选择关联工单，以便用料去向可追溯。

**验收标准**
- Given 录入出库单，When 在表单中选择"关联工单"（可选，下拉搜索），Then 单据保存 `related_order_id`。
- 仅出库单可关联工单；入库单默认不显示该字段。
- 单据流水列表显示关联工单号，可点击跳转工单详情。
- 工单详情"物料领用"聚合展示所有关联出库单（与 P1-05 视图一致）。
- `related_order_id` 为空时不影响 P0 原有出入库流程（向后兼容）。

**依赖与前置**：`StockDocument.related_order_id`（P0 已预留可空字段）；P1-07。

### P1-09 库存预警站内消息推送（顺序 10）

**用户故事**
- 作为仓管员，我想在库存低于阈值时收到站内消息，以便及时补货而不必一直盯着库存列表。

**验收标准**
- Given 某物料库存经出库/领料后 `quantity <= warn_threshold`，When 单据提交成功，Then 生成一条站内消息推送给仓管员（`keeper` 角色用户），含物料/仓库/当前库存/阈值。
- Given 库存仍处低位，When 后续无关操作，Then 不重复推送同一低库存事件（同一"仓库+物料"在低位期间只触发一次，回升后再次跌破可再推，默认假设 A4）。
- 顶部消息角标/站内消息中心可见该消息，点击跳转库存页。
- 消息可标记已读。
- 推送失败不得影响出入库主流程（容错；默认失败仅记录日志、不回滚单据）。

**依赖与前置**：P1-07（单据提交钩子）；站内消息载体（见 §6 `Notification`）；`keeper` 角色用户。

### P1-10 文件可见范围细化到部门（顺序 11）

**用户故事**
- 作为档案管理员，我想把文件设为"仅指定部门可见"，以便部门资料精准共享。
- 作为员工，我想只看得到授权给本部门的文件，以便不越权访问。

**验收标准**
- Given 上传/编辑文件时，When 可见范围选"指定部门"，Then 可多选部门并保存到关联表。
- `visibility_type` 扩展为 `all` / `roles` / `departments` 三值（P0 已有前两值）。
- Given 员工登录，When 浏览文件列表，Then 可见 = 全部 `all` 文件 ∪ 角色命中的 `roles` 文件 ∪ 部门命中的 `departments` 文件（含子部门，默认假设 A5）。
- Given 直接访问未授权文件的下载/预览 URL，When 请求，Then 返回 403。
- 管理员修改可见范围后即时生效。

**依赖与前置**：`FactoryFile.visibility_type` 取值扩展；新增部门可见关联表；P0 文件可见范围机制。

### P1-11 文件检索（顺序 12）

**用户故事**
- 作为员工，我想按文件名关键词和分类筛选文件，以便快速找到需要的资料。

**验收标准**
- Given 文件列表页，When 在搜索框输入名称关键词，Then 过滤出名称包含关键词的**可见**文件（服务端过滤）。
- When 选择分类树节点，Then 仅显示该分类及子分类下的可见文件。
- 名称关键词与分类可组合筛选，结果支持分页。
- 搜索结果始终受可见范围约束（P1-10），越权文件不出现在结果中。

**依赖与前置**：P1-10（统一可见性过滤出口，检索复用同一出口）。

### P1-12 在线预览图片/PDF（顺序 13）

**用户故事**
- 作为员工，我想在浏览器中直接预览图片和 PDF 文件，以便无需下载即可查看资料。

**验收标准**
- Given 文件为图片（`png/jpg/jpeg/gif/webp`）或 `PDF`，When 点击"预览"，Then 在新标签或 Bootstrap5 模态框中内联展示（响应头 `Content-Disposition: inline`）。
- Given 其他格式（doc/xls/ppt 等），When 查看操作列，Then 不显示"预览"按钮，仅保留"下载"。
- 预览同样校验可见范围，越权返回 403。
- 预览页沿用 Jinja + Bootstrap5 风格，含文件名与"下载"入口。
- 预览不改变 P0 上传大小上限（50MB）与白名单策略。

**依赖与前置**：P1-10（可见范围）；权限点 `files.view`。

### P1-13 聊天历史分页加载（顺序 15）

**用户故事**
- 作为员工，我想在聊天窗口中分页加载历史消息，以便快速打开会话而不必一次性拉取全部记录。

**验收标准**
- Given 打开会话，When 进入聊天页，Then 默认加载最近 N 条（默认 20）消息并滚动到底部。
- When 点击"加载更早消息"或上滚触发，Then 按 `before_id` 加载上一页并追加到顶部，保持滚动位置不跳动。
- 无更多历史时显示"没有更多消息"。
- 分页仅加载当前会话双方的消息，不串会话。
- 与 P0 增量拉取接口（`after_id`）共存且不冲突。

**依赖与前置**：聊天服务分页查询（新增 `before_id/limit` 参数）；`chat_service`。

### P1-14 未读计数精确化（顺序 14）

**用户故事**
- 作为员工，我想导航栏未读角标精确反映"尚未查看的消息条数"，以便不漏消息也不被重复计数干扰。

**验收标准**
- Given 用户离线期间收到 N 条消息，When 重新登录/刷新，Then 角标显示精确未读条数 N（按消息条数，非会话数）。
- Given 打开与某人的会话，When 查看，Then 该会话未读清零，角标相应减少（只减该会话的量）。
- Given 同一会话多轮收发，When 计算未读，Then 已读消息不再计入（基于持久化的"最后已读消息位点"，而非浏览器 session）。
- 多设备/多标签以服务端持久化的已读位点为准（按 `user + peer` 记录 `last_read_message_id`，默认假设 A3）。
- `/chat/api/unread` 返回按会话分组的精确计数，与顶部角标一致。

**依赖与前置**：会话已读位点载体（见 §6 `ConversationRead`）；`chat_service`。

---

### P1-15 全局操作日志（顺序 1）

**用户故事**
- 作为系统管理员，我想记录关键操作（登录、人员增删改、请假审批、出入库、领料、权限变更、导出等）的操作人与时间，以便审计与追责。

**验收标准**
- Given 发生关键操作，When 操作成功，Then 写入 `OperationLog`：操作人、模块、动作类型、目标类型+ID、摘要、IP、时间（统一经 `app/utils/time_utils.now()`，Asia/Shanghai naive）。
- 日志记录与业务数据在同一事务提交；仅成功操作留痕（失败操作不记成功日志）。
- Given 管理员打开"系统→操作日志"，When 按模块/操作人/时间/动作筛选，Then 分页展示；可作为 P1-16 导出数据源（可选）。
- 日志只读，任何角色不得编辑/删除。
- 提供统一 `log_operation()` 服务供各模块调用；工单日志（P1-06）复用同一表。

**依赖与前置**：`OperationLog` 模型；权限点 `system.log.view`；统一日志服务。

### P1-16 数据导出 CSV（顺序 16）

**用户故事**
- 作为管理员/部门主管，我想把人员、考勤、库存数据导出为 CSV，以便离线汇总与上报。

**验收标准**
- Given 在人员/考勤汇总/库存列表页，When 点击"导出 CSV"，Then 导出**当前筛选结果**（遵循数据权限与当前筛选条件）的 CSV 文件。
- 导出字段：人员（工号/姓名/部门/岗位/手机/邮箱/状态）、考勤（部门/姓名/日期/签到/签退/状态/迟到早退分钟）、库存（仓库/物料/编码/规格/数量/阈值/状态），最终字段以评审为准。
- CSV 采用 UTF-8 BOM（Excel 中文不乱码），文件名含导出日期。
- 不含密码哈希等敏感字段；手机号/邮箱默认导出原值（内网可信，见默认假设 A1），导出行为记入操作日志（P1-15）。
- 越权数据不进入导出（P1-04 生效）；单次导出设行数上限（默认 10000 行，超出提示缩小范围，见默认假设 A1）。

**依赖与前置**：P1-04（数据权限）、P1-15（导出留痕）；权限点 `system.export`；各模块字段稳定。

## 5. 权限点增量

### 5.1 新增权限点清单

> 全部遵循 `模块.动作` 命名，且**必须在 `app/utils/permissions.py` 的 `PERMISSION_REGISTRY` 中唯一声明**（与 P0 约定一致）；种子脚本同步进 `Permission` 表。角色 code 沿用 P0 内置角色：`superadmin/leader/keeper/producer/staff/archivist`。

| 权限点 | 中文名 | 默认拥有角色 | 关联需求 | 说明 |
|---|---|---|---|---|
| `attendance.leave.apply` | 请假申请 | staff、leader、producer、keeper、archivist、superadmin（全体业务角色） | P1-01 | 提交请假申请 |
| `attendance.clock`（P0 权限，此处重申） | 考勤打卡 | **全体内置角色**（staff/leader/keeper/producer/archivist/superadmin） | P1-01 | 工厂所有员工均可打卡，含主管/仓管/生产/档案角色 |
| `attendance.leave.approve` | 请假审批 | leader、superadmin | P1-01 | 审批本部门请假（受数据权限约束） |
| `attendance.summary.view` | 部门考勤汇总 | leader、superadmin | P1-03 | 查看部门考勤汇总 |
| `production.issue` | 工单领料 | producer、keeper、superadmin | P1-05 | 发起领料/关联出库 |
| `warehouse.ledger.view` | 库存流水查询 | keeper、superadmin | P1-07 | 查看库存变动流水 |
| `system.log.view` | 操作日志查看 | superadmin | P1-15 | 查看全局操作日志 |
| `system.export` | 数据导出 | superadmin、leader（受数据权限约束） | P1-16 | 导出人员/考勤/库存 CSV |

**复用现有权限点（不新增）**：
- `attendance.view_all`：仍用于控制"查看他人考勤"的全量能力；数据权限（P1-04）与其叠加——主管即便持 `attendance.view_all` 也只在本部门范围内生效。
- `files.view`：文件预览（P1-12）、检索（P1-11）复用，叠加可见范围校验。
- `warehouse.manage`：出入库单据关联工单（P1-08）、领料（P1-05）由 `warehouse.manage` 或 `production.issue` 分别覆盖。
- 库存预警推送（P1-09）、未读精确化（P1-14）、历史分页（P1-13）、工单操作日志查看（P1-06）为能力增强，复用对应模块 `view/manage` 权限点，不新增。

### 5.2 数据权限（部门隔离）实现边界

- **作用对象**：持 `leader` 角色且为某 `Department.leader_id` 的用户；`superadmin` 完全豁免；其他角色维持 P0 现状。
- **过滤范围**：人员（`hr`）、考勤（`attendance` 月度/汇总/审批）、工单（`production`，按 `related_department_id` 或负责人归属）三类列表与统计。
- **部门口径**：本部门 + 所有下级部门（递归，见默认假设 A5）。
- **实现边界**：仅在**读查询出口**（各蓝图 `base_query`）注入过滤条件；不改动写操作的权限判定；不新增"数据权限"权限点，属于横向数据收窄。
- **与功能权限关系**：数据权限是"交集"而非"并集"——先过 `@permission_required` 功能权限，再过部门数据过滤，两者都满足才可见。
- **一致性要求**：CSV 导出（P1-16）必须复用同一 `base_query`，确保"能看多少就能导多少"。

## 7. 待确认问题与默认假设

> 若评审无异议，按"默认假设"执行；如有不同决策请主理人在评审时明确。

| 编号 | 待确认问题 | 默认假设 | 影响需求 |
|---|---|---|---|
| **A1** | CSV 导出是否含敏感字段脱敏？单次导出行数是否设限？ | 不含密码哈希；手机号/邮箱导出**原值**（内网可信环境）；单次上限 **10000 行**，超出提示缩小筛选范围；导出行为记入操作日志 | P1-16 |

| **A4** | 库存流水期初如何记入？预警推送去重策略？推送失败如何处理？ | 首次/期初入库记为"入库"流水、变动前余额=0；同一"仓库+物料"在低库存期间只推一次，回升后再跌破可再推；推送失败仅记日志、不回滚单据 | P1-07/P1-09 |
