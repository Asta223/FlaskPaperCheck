## 一、背景与范围

用户线下反馈"小工厂也有排产需求"。排产能力拆四层推进：

| 层 | 内容 | 本期 |
|---|---|---|
| L0 交期管理 | `WorkOrder.due_date`（只记何时交） | 已具备 |
| **L1 粗排产（倒排）+ 超期预警** | 交期 + 工序参考工时 → 倒推"最晚该哪天开工"，提前暴露超期风险，改动最小 | **本期范围** |
| L2 有限产能排程 | 班组/产线负荷、甘特图 | 不做，留后续 |
| L3 APS 求解器 | 智能排程 | 明确不做 |

L1 定位：**只算日期、只做提醒**。不排具体机台/人，不改工单状态机，不追求最优解。目标是让生产者"提前知道哪单要来不及"，而不是"自动安排生产"。

## 二、目标与非目标

**产品目标（3 个，正交）：**
1. **可倒推**：每个有交期的工单，能按参考工时自动算出"计划完工日 / 最晚开工日"。
2. **早预警**：临期或已过最晚开工日的未完工工单，在列表/看板一眼可见（标红）。
3. **可人工兜底**：自动算出的日期允许人工覆盖，覆盖后不被自动重算冲掉。

**非目标（本期不做）：** L2 产能排程、L3 APS、BOM/物料需求展开、班组/产线/机台维度、甘特图、自动调整交期、审批流。

## 三、用户故事

1. 作为**生产管理员**，我希望新建工单填了交期后系统自动告诉我"最晚 X 月 X 日必须开工"，以便提前备料安排。
2. 作为**生产管理员**，我希望在工单列表/看板看到哪些单"倒排剩余天数"已为负，以便优先催办。
3. 作为**车间负责人**，我希望交期已过但还没完工的单据标红，以便一眼识别确定性超期。
4. 作为**生产管理员**，当参考工时不准时，我希望能手动改计划日期，且系统下次自动重算不要覆盖我的修改。
5. 作为**生产管理员**，我希望改了交期或工序后能一键"重新倒排"，以便计划日期跟着更新。

## 四、功能需求

> 优先级：P0 必须 / P1 应该 / P2 可选。

### FR1 计划字段（P0）
`WorkOrder` 新增 `plan_start_date`（计划开工日）、`plan_end_date`（计划完工日）、`priority`（优先级）。取值与默认见「数据字典增量」。`priority` 本期**仅存储/展示/排序**，不参与倒排计算（为 L2 预留）。

### FR2 日产能配置（P0）
- **默认值：`DAILY_CAPACITY_HOURS = 8`（小时/天）**，口径为"单班组/单线的粗略日产能"。
- 配置方式：在 `config.py` 的 `Config` 新增该常量，支持环境变量 `DAILY_CAPACITY_HOURS` 覆盖（沿用现有 `.env` / 环境变量读取机制，零新增依赖）。**全局单一值**，L1 不区分班组/产线/工序。
- > 假设：8 小时/天为通用默认；小工厂可按实际在配置层调整一次即可，无需按工单配置。

### FR3 倒排计算口径（P0）
由 `app/services/scheduling_service.py` 统一实现，服务端唯一计算口径：

```
H_total = Σ(各工序 standard_hours) × quantity         # 单件各工序参考工时之和 × 数量（小时）
D       = max(1, ceil(H_total / DAILY_CAPACITY_HOURS)) # 需要工作日数，向上取整，至少 1 天
plan_end_date   = due_date                             # 计划完工日 = 交期（原值）
plan_start_date = 从 plan_end_date（含）向前取第 D 个工作日
```

- `standard_hours` 取工序档案 `Process.standard_hours`（单件单工序参考工时）；工单工序行项若无法关联工序（历史数据 `process_id` 为空）或其工时为 0/空，该步按 0 计。
- **工作日历**：仅周一~周五为工作日，**不含法定节假日**（沿用 `time_utils.workdays_in_month` 的简化口径）；倒排按工作日回退，跳过周末。需新增"向前取第 N 个工作日 / 两个日期间工作日差"的工具函数（放 `time_utils.py`）。
- **取整**：天数一律 `ceil`（向上），保证不低估工期；不足 1 天按 1 个工作日。
- > 假设：交期当天即视为完工日；若交期落在周末，`plan_end_date` 仍保留交期原值，但回退时该周末日不计入工作日、也不作为开工日。

### FR4 自动计算与人工覆盖（P0）
- **自动算**：新建工单保存、编辑工单保存（含数量/交期/工序变更）时，若未标记人工覆盖，调用 FR3 重算并写入计划字段。
- **人工覆盖**：编辑页可手工填写/修改 `plan_start_date`、`plan_end_date`；保存时若与自动值不同，置 `plan_manual = True`（见 FR5 字段说明），此后自动计算**不再改写**这两个日期。
- **标记可见**：列表/详情对人工覆盖的计划日期显示"人工"小标记，便于识别。
- **解除覆盖**：通过"重新倒排"入口显式清除标记并回到自动计算（见 FR6）。

### FR5 人工覆盖标记字段（P0，PM 建议）
为可靠实现 FR4，需第 4 个字段 `plan_manual`（Boolean，默认 `False`）随本次迁移一并加上：`False`=自动计算可写，`True`=保留人工值。
> 说明：主理人原始方案列了 3 个字段；`plan_manual` 是实现"人工覆盖不被冲掉"所必需的最小标记，建议纳入同一迁移。若团队决定仅上 3 字段，则退化方案为"任何手工改计划日期即视为一次性覆盖、下次编辑工单不再自动重算"，但无法精确识别覆盖状态——**PM 推荐采用 `plan_manual`**。

### FR6 重新计算入口（P0）
- 工单详情/列表行操作提供"重新倒排"按钮：调用 FR3 重算、`plan_manual` 置回 `False`，成功后刷新页面并给出结果提示。
- 批量"刷新全部工单计划"列为 P2 可选，本期不做。

### FR7 倒排剩余天数展示（P0）
列表（`production.order_list`）与看板（`production.board`）新增两列：
- **计划开工日**：`plan_start_date`（`fmt_date` 格式化，空显示 `-`）。
- **倒排剩余天数** = 按工作日计算的 `plan_start_date - today()`：`>0` 显示"还剩 N 个工作日"；`=0` 显示"今天最晚开工"；`<0` 显示"已过 N 个工作日"。无计划日期显示 `-`。
- 仅周一~周五计、忽略节假日；`today()` 统一走 `app/utils/time_utils.py`。

### FR8 超期判定与标红（P0）
对**未完工工单**（`status ∈ {pending, in_progress}`）整行标红，并打标签：
- **已超期**：`due_date < today()`（交期已过仍未完工）→ 标签"已超期"。
- **开工预警**：`plan_start_date <= today() <= due_date`（最晚开工日已到/已过，仍未完工）→ 标签"开工预警"。
- 两者同时命中时以"已超期"优先展示。已完成/已验收工单不标红；无计划日期且无"已超期"命中者不标红。
- 标红仅前端提示（Bootstrap 行样式 + 文字标签），**不改状态机、不拦截操作、不发新通知**（与 L1 轻量定位一致）。

## 五、关键业务规则与边界

| 场景 | 处理 |
|---|---|
| 无交期（`due_date` 空） | 不倒排，计划日期留空，剩余天数显示 `-`，不参与超期标红；`priority` 仍可维护 |
| 无工序 / 工序参考工时合计为 0 | 无法估算工期 → 计划日期留空，提示"未维护工序参考工时，无法倒排"，不伪造"1 天开工"，不标红 |
| 部分工序工时为 0 | 只累加有效工时；若合计仍为 0 按上一条处理 |
| 交期已过（`due_date < today`） | 仍按公式倒排计划日期；同时直接命中"已超期"标红 |
| 交期落在周末 | `plan_end_date` 保留交期原值；回退仅计工作日，周末不作为开工日 |
| 历史工单（无工序 `process_id`） | 迁移后计划字段为空，不回填、不伪造；用户编辑保存时按现有工序重算 |
| 已完工工单 | 保留已有计划日期供追溯，但不参与自动重算与标红 |

## 六、数据字典增量（`work_orders` 表）

| 字段 | 类型 | 可空 | 默认 | 说明 |
|---|---|---|---|---|
| `plan_start_date` | Date | 是 | NULL | 计划开工日（倒推的最晚开工日） |
| `plan_end_date` | Date | 是 | NULL | 计划完工日（= 交期） |
| `priority` | String(10) | 否 | `'normal'` | 取值 `high`/`normal`/`low`（高/普通/低），本期仅展示排序 |
| `plan_manual` | Boolean | 否 | `False` | 【PM 建议，FR5】人工覆盖标记；`True` 时自动重算不改写计划日期 |

一次 Alembic 迁移完成，历史数据三日期字段为 NULL、`priority='normal'`、`plan_manual=False`。新增权限点/菜单：**无**（沿用 `production.view` 与现有工单编辑权限）。

## 七、验收标准

- [ ] 迁移后 `work_orders` 新增上述字段，已有工单不受影响，`flask db upgrade` 可重复执行无障碍。
- [ ] 新建工单填交期并配置工序后保存，`plan_end_date = due_date`，`plan_start_date` 按 FR3 公式得出且落在工作日。
- [ ] 改数量/交期/工序后保存，未覆盖的计划日期自动重算，结果与 FR3 一致。
- [ ] 手工改计划日期保存后 `plan_manual=True`，再次编辑工单计划日期不被自动改写，且显示"人工"标记。
- [ ] 点击"重新倒排"后计划日期按公式刷新、`plan_manual=False`。
- [ ] 列表/看板正确显示"计划开工日""倒排剩余天数"，正数/0/负数三种文案正确。
- [ ] 交期已过的未完工工单整行标红并标"已超期"；最晚开工日已到的标"开工预警"；已完工工单不标红。
- [ ] 无交期、无工序、工时为 0 的工单按第五节边界处理，不报错、不误标红。
- [ ] `DAILY_CAPACITY_HOURS` 默认值 8，可通过环境变量覆盖并影响倒排结果。
- [ ] 全量 pytest 通过；新增倒排计算/边界的单元测试。

## 八、明确不做（Out of Scope）

- **L2 有限产能排程**：班组/产线负荷、机台占用、甘特图、并行工序排布。
- **L3 APS 求解器**及任何智能优化。
- **BOM / 物料需求展开 / 齐套检查**（领料仍走现有流程）。
- 按工序/班组分别配置产能、考虑节假日/调休日历、考虑换线/模具等约束。
- 自动改交期、审批流、新通知类型、批量重算（P2 可选）。

## 九、开放问题（不阻塞开工，已给默认假设）

1. `plan_manual` 是否纳入本次迁移——PM 推荐纳入（FR5）；若否按退化方案执行。
2. 日产能 8 小时/天是否符合现场——已给默认值与配置入口，上线前可由用户调整一次。
3. "倒排剩余天数"是否需要在看板卡片而非仅列展示——本期列表/看板均加列，卡片样式由工程按现有看板结构落地。
