# PRD：小型工厂管理系统

> 版本：v1.0 ｜ 作者：许清楚（产品经理）｜ 状态：待评审
> 项目代号：`factory-mgmt`

---

## 1. 产品目标与背景

本项目面向**小型工厂（几十至几百人）**，采用 Flask 应用工厂 + Flask-Login + Flask-Migrate + Bootstrap5/Jinja2 的单体架构，内网单机部署。

**产品目标：**

1. **业务覆盖**：以人员/部门/权限/考勤/生产/文件/仓库/物料/聊天 9 大模块覆盖工厂日常管理，服务端渲染 + Bootstrap5，中文界面。
2. **轻量复用**：基于统一的登录认证、数据库迁移（Alembic）、应用工厂/蓝图结构与环境变量配置，控制实现与维护成本。
3. **简单可用**：内网单机部署，简单 RBAC 自建权限，聊天用轮询，不引入前后端分离与重量级依赖，保证几十到几百人规模下流畅、易维护。

## 2. 用户角色定义

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| **系统管理员** | 工厂信息化负责人，全权限 | 管员工/部门/角色权限，配置考勤规则、库存预警阈值，保障系统运行 |
| **部门主管** | 部门负责人 | 查看本部门人员与考勤、审批请假、下达/跟踪本部门生产工单进度 |
| **仓管员** | 仓库管理员 | 录入出入库单据、查询库存、收到库存预警后及时补货 |
| **生产管理员** | 生产/车间调度人员 | 创建生产工单、分配工序、更新流转状态、看板掌握全局进度 |
| **普通员工** | 一线员工 | 打卡签到、提交请假申请、查看个人考勤、收发站内消息、查看被授权的文件资料 |
| **档案管理员**（可由行政兼任） | 负责 P0/P1 文件资料 | 上传分类工厂文档/图纸，控制可见范围（全员/指定部门/指定角色） |

> 角色与权限采用自建简单 RBAC：Role 表 + Role-Permission 关联，权限点对应"菜单/页面 + 操作"两级；用户属一个部门，可挂多个角色。系统管理员为内置角色。

## 3. 用户故事（按模块）

**人员管理**
- 作为系统管理员，我要录入/编辑员工档案（姓名、工号、部门、岗位、联系方式、入职/离职日期），以便维护人员台账。
- 作为系统管理员，我要为员工办理离职（停用账号并保留历史数据），以便人员离职后无法登录但考勤/单据记录不丢失。

**部门管理**
- 作为系统管理员，我要以树形结构维护部门及上下级，并指定部门负责人，以便组织架构清晰、归属明确。

**权限管理**
- 作为系统管理员，我要创建角色并勾选其可访问的菜单与操作，以便不同岗位只见所需功能。
- 作为部门主管，我要只能查看/审批本部门相关的数据，以便数据权限隔离。

**考勤管理**
- 作为普通员工，我要在网页上签到/签退（每日一次），以便记录出勤。
- 作为部门主管，我要查看本部门月度考勤统计（出勤/迟到/缺卡），并审批员工的请假申请，以便掌握部门出勤情况。

**生产进度管理**
- 作为生产管理员，我要创建生产工单（产品、数量、交期、负责人），以便车间按单生产。
- 作为生产管理员，我要按工单维护工序及状态流转（待开始→进行中→已完成→验收），并通过进度看板查看全部工单，以便及时调度。

**文件管理**
- 作为档案管理员，我要按分类上传工厂文档/图纸（支持常见格式），并设置可见范围，以便资料有序共享、不越权访问。
- 作为普通员工，我要按分类浏览和下载我被授权的文件，以便查阅作业资料。

**仓库管理**
- 作为仓管员，我要录出入库单据（物料、数量、经手人、关联工单可选），以便库存随单据自动增减。
- 作为仓管员，我要查询各仓库实时库存，并在库存低于预警阈值时收到提醒，以便及时补货。

**物料管理**
- 作为系统管理员/仓管员，我要维护物料档案与分类（编码、名称、规格、单位），并与仓库库存关联，以便物料基础数据统一。

**站内聊天**
- 作为员工，我要选择同事发起会话、收发消息，并在导航栏看到未读数提醒，以便内网快速沟通。

## 4. 需求池

### P0 — 必须有（MVP）

| 模块 | 需求 |
|---|---|
| 基础（复用） | 登录/登出、修改密码（复用 Flask-Login）；应用工厂 + 蓝图重组；alembic 迁移重建表结构；环境变量配置沿用 |
| 权限管理 | Role/Permission 表 + 用户-角色绑定；装饰器级访问控制（`@permission_required`）；菜单按权限渲染；内置"系统管理员"角色 |
| 人员管理 | 员工档案 CRUD（工号、姓名、部门、岗位、手机、邮箱、入职日期、状态）；离职=停用账号（is_active） |
| 部门管理 | 部门表（parent_id 树形）CRUD、指定部门负责人；员工归属部门（单部门） |
| 考勤管理 | 每日签到/签退打卡；个人打卡记录查询；月度出勤统计（出勤/缺卡天数） |
| 生产进度管理 | 工单 CRUD（单号、产品名称、数量、交期、负责人、状态）；工序行项与状态流转（待开始/进行中/已完成）；简单进度看板页（按状态分组展示） |
| 仓库管理 | 仓库档案；入库/出库单据录入；库存表随单据自动增减；库存列表查询；库存低于阈值列表标红提示（P0 仅页面提示） |
| 物料管理 | 物料档案/分类 CRUD（编码、名称、规格、单位）；物料与库存关联查询 |
| 文件管理（基础） | 文件上传（复用现有 uploads 机制）、分类管理、文件列表/下载；可见范围控制（全员/指定角色） |
| 站内聊天（基础） | 用户间一对一消息收发；会话列表；导航栏未读数；AJAX 轮询（10~15s）拉取新消息 |
| 页面框架 | 左侧导航 + 顶部栏布局（复用 base.html），全中文界面 |

### P1 — 应该有

| 模块 | 需求 |
|---|---|
| 考勤管理 | 请假申请 + 部门主管审批流；迟到/早退判定规则；部门主管查看本部门考勤汇总 |
| 权限管理 | 数据权限：部门主管仅见本部门人员/考勤/工单数据 |
| 生产进度管理 | 工单与物料出库关联（领料）；工单操作日志 |
| 仓库管理 | 库存变动流水明细；出入库单据关联工单；库存预警站内消息推送 |
| 文件管理 | 可见范围细化到指定部门；文件检索（按名称/分类）；在线预览图片/PDF |
| 站内聊天 | 历史消息分页加载；离线消息未读计数精确化 |
| 系统通用 | 操作日志（关键操作留痕）；数据导出 CSV（人员/考勤/库存） |

### P2 — 可选

| 模块 | 需求 |
|---|---|
| 物料管理 | 简易 BOM（产品-物料清单）；物料需求测算 |
| 生产进度管理 | 看板可视化图表（ECharts 进度/达成率）；工单延期提醒 |
| 考勤管理 | 考勤规则配置化（班次、弹性时间）；补卡申请 |
| 仓库管理 | 多仓库调拨单；库存快照/盘点 |
| 人员管理 | 员工头像、入职附件；部门架构可视化图 |
| 站内聊天 | 群组/部门广播消息；图片附件 |
| 系统通用 | 简单首页工作台（待办汇总：待审批请假、预警库存、进行中工单） |

### 基础能力清单

- **登录认证**：Flask-Login + User 模型 + RBAC 角色关联
- **数据库迁移**：Flask-Migrate/Alembic 单一线性迁移链
- **配置管理**：config.py 环境变量驱动（DATABASE_URL / DB_ENGINE=sqlite）
- **文件上传**：统一使用 data/uploads，路径由 config 配置
- **前端骨架**：Bootstrap5 CDN + base.html 继承体系，导航按工厂业务组织

## 5. UI 设计稿说明（文字描述）

**整体框架**：沿用 base.html —— 顶部栏（左侧系统名"工厂管理系统"+ 全局搜索/站内消息图标（含未读角标）+ 用户下拉菜单）+ 左侧固定导航（按权限动态渲染菜单组）+ 右侧主内容区（面包屑 + 卡片式内容）。Bootstrap5 风格，中文界面。

| 页面 | 布局要点 |
|---|---|
| 登录页 | 居中卡片，账号/密码 + 登录按钮，品牌区显示系统名 |
| 工作台/首页 | 顶部统计卡片行（我的工单、待审批、库存预警数、未读消息）；下方"进行中工单"简表 + 快捷入口 |
| 人员管理 | 左：部门树（可点击筛选）；右：员工表格（搜索框 + 分页），行内"编辑/停用"按钮；新建员工为模态框表单 |
| 部门管理 | 左右分栏：左侧部门树（支持增删改节点），右侧选中部门详情（负责人、下属员工列表） |
| 角色权限 | 左：角色列表；右：权限勾选矩阵（按模块分组的功能/菜单 checkbox）；用户编辑页内多选角色 |
| 考勤打卡 | 顶部醒目"签到/签退"大按钮 + 当日状态；下方月历或月度表格展示个人考勤；主管视角为部门汇总表 + 待审批请假列表 |
| 生产工单 | 列表页（筛选：状态/负责人/日期）+ 新建/编辑表单；详情页上半为工单信息，下半为工序步骤时间线（状态标签可流转）；看板页为按状态分列的卡片视图（待开始/进行中/已完成） |
| 仓库管理 | 库存列表页（仓库/物料筛选，低于阈值的数量红色标注）；出入库录入为表单页（选物料+数量+备注）；单据流水表 |
| 物料管理 | 分类侧栏 + 物料表格 CRUD；详情页含各仓库库存分布 |
| 文件管理 | 左：分类目录树；右：文件列表（名称/大小/上传人/时间 + 下载按钮）；上传按钮弹模态框（选分类、可见范围） |
| 站内聊天 | 两栏布局：左会话列表（最近联系人 + 未读数），右聊天窗口（消息气泡 + 底部输入框），JS 轮询刷新 |

## 6. 待确认问题（含默认假设）

1. **旧数据是否保留？**
   默认假设：历史业务数据不做迁移；User 表结构沿用作为员工账号基础。若需保留历史账号请反馈。

2. **考勤是否需要请假审批流（P1）在 MVP 中体现？**
   默认假设：MVP 仅做打卡 + 统计，请假审批放 P1。若客户强烈要求，可将"请假申请/审批"提升至 P0。

3. **生产工单与仓库是否强关联？**
   默认假设：MVP 中工单与出入库单据独立，不强制领料关联（关联放 P1）。若车间领料是核心痛点，需提升优先级。

4. **库存预警的触发方式？**
   默认假设：P0 仅在库存列表页红色标注低于阈值物料；P1 增加站内消息推送。是否需要邮件/短信提醒？（默认不做，内网环境）

5. **聊天是否需要群聊？**
   默认假设：MVP 仅一对一私聊 + 轮询；群聊/部门广播放 P2。
